# Eredivisie

A machine learning project that predicts Eredivisie match results.

## Team — "Kabollenbappers"

- Daan Sijmens
- Tristan Voermans
- Tristan Veldkamp

## Goal

Together with 2 friends, I will spend 2 hours a week predicting Eredivisie matches using a model I build.

## SMART Breakdown

| | |
|---|---|
| **Specific** | Study historical match results, build a simple model, and predict the scores for every matchday before kick-off. |
| **Measurable** | Correctly predict the scores 70% of the time, using data from the past 2 seasons to predict the results of the matches in the next 8 weeks. |
| **Achievable** | 2 hours per week fits in our schedule (e.g. evenings or weekends). The model starts simple, using the results of the last 5 matches, and we work together so we can help each other when stuck. The winter break shortens the season, so we count at least 5 matchdays rather than a fixed number. |
| **Relevant** | Real data science work is teamwork, so dividing tasks, sharing code, and combining results builds skills that solo coursework doesn't. Sports prediction is also a classic data science problem. |
| **Time-bound** | **Week 1:** collect last and this season's data, make the 80/20 split, and build a baseline model together. **Weeks 2–3:** improve the model and start predicting before kick-off. **Week 4:** halfway check. **Weeks 5–7:** add each matchday's results, retrain, and predict the next one. **Week 8:** final check on all matchdays and review what worked and what didn't. |

## Evaluation

Evaluate at the end of week 4 whether our model beats the home-team rule, and whether the roles and weekly check-in are working well for all three of us.

## Revision

Revise the model if it loses to the home-team rule, for example by adding recent form or goal difference. Adjust roles or meeting times if one person is doing too much or too little.
